## 11827-2 — Recuperación de herramientas mixtas sin cortar el turno

**Problema confirmado**:

- El proveedor podía devolver en una misma respuesta una herramienta web interna y una herramienta que
  debía ejecutar el cliente. El bridge lanzaba `502` inmediatamente y terminaba el turno con
  `response.failed`.

**Qué se hizo**:

- El web loop ahora ejecuta primero las llamadas web internas, conserva sus resultados emparejados y
  reintenta con una directiva explícita para que el modelo emita solo las herramientas del cliente o
  la respuesta final.
- La recuperación es configurable mediante `BRIDGE_MIXED_TOOL_RECOVERY_RETRIES`, con valor 1 y
  máximo 2; el presupuesto total de rondas se deriva para conservar una ronda final de finalización.
- Los argumentos de las llamadas pendientes no se interpolan en mensajes `system`; solo se pasan los
  nombres de herramientas para que el modelo regenere argumentos desde el contexto original.
- Streaming y no-streaming usan la misma implementación. Si el proveedor insiste tras el límite,
  queda un error explícito y bounded (`mixed_tool_recovery_exhausted`), evitando bucles infinitos.

## 11827-3 — Auditoría de cierre no puede completar turnos inconclusos

**Problema confirmado**:

- Tras un error de herramienta, el modelo podía anunciar una corrección sin emitir el siguiente
  `tool_call`. Si el nudge agotaba su timeout, el bridge conservaba el texto y cerraba con
  `response.completed`/`end_turn=true`.

**Qué se hizo**:

- El nudge ahora devuelve estados explícitos: `tool_calls`, `confirmed`, `inconclusive_unconfirmed`,
  `inconclusive_timeout` e `inconclusive_error`.
- Una narración intermedia sin herramienta ni confirmación se conserva como contexto y recibe otra
  directiva de ejecución obligatoria. El bridge permite hasta 3 rondas por defecto, con máximo de
  intentos y presupuesto total configurables mediante `BRIDGE_NUDGE_MAX_ATTEMPTS`,
  `BRIDGE_NUDGE_BUDGET_MS` y
  `BRIDGE_NUDGE_TIMEOUT_RECOVERY_MS`.
- Los timeouts también tienen una recuperación acotada dentro del mismo límite; no se convierten en
  un `end_turn` exitoso.
- Streaming, navegador interno y no-streaming emiten `response.failed`/HTTP 502 ante una auditoría
  inconclusa. Una herramienta web no resoluble en no-streaming tampoco puede ocultarse y producir
  `status: completed`.
- Se añadieron regresiones para timeout, recuperación exitosa, respuesta sin confirmación, web loop y
  error de renderizado de herramientas.
