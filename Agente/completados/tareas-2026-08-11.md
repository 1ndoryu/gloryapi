## 11826-1 — Hook universal de confirmación de cierre en el bridge de Codex Desktop

**Qué se hizo** (sustituye la heurística de `10826-1`; el diagnóstico del thread
`019fee99` mostró que "Sigo la auditoría leyendo..." —gerundio de continuación— no
matcheaba la regex y el falso complete volvía a escaparse):

El usuario pidió que, en vez de adivinar con una heurística, el bridge **pregunte al
modelo** si realmente terminó. El hook es universal: toda respuesta final sin
`tool_calls` (con tools del usuario disponibles y sin haber ejecutado ninguna tool en
el turno) recibe UN request de confirmación con `CONFIRM_DIRECTIVE`: si realmente
terminó, que responda únicamente "ok"; si le queda algo, que continúe en el mismo
turno invocando la herramienta. "ok" confirma el cierre **sin re-activar el hook**;
cualquier otro texto se descarta y se cierra con la respuesta original.

- **`CONFIRM_DIRECTIVE`** (reemplaza `NUDGE_DIRECTIVE`): texto de confirmación de
  cierre ("si realmente has terminado... responde únicamente 'ok'... si no,
  continúa AHORA...").
- **`isConfirmationText(text)`**: detecta la confirmación concreta (ok/okay/okey/kk/
  done/yes/sí/listo/hecho/terminado/completado/finished/all done/eso es todo/ya
  está/nada más/perfecto/vale/de acuerdo/entendido/confirmado + variantes "ok
  done/listo/hecho/..."). Normaliza puntuación a espacios y **rechaza "ok, pero
  falta X"** (no es cierre real).
- **Gatillo universal** (streaming y non-streaming): `tool_calls` vacíos + texto +
  `chat.__userTools === true` (tools del usuario, no las inyectadas
  `node_repl`/`automation_update`) + tools presentes + **sin `tool` messages en el
  turno** (si ya ejecutó, el cierre es legítimo y no se pregunta) + `NUDGE_RETRIES>0`.
- **`__userTools`**: flag no-enumerable en `translateRequest` (no se serializa a
  upstream). En `runInternalWebToolLoop` el spread no copia no-enumerables → se
  re-define en `working`; el non-streaming usa `gateChat = resolved.working` para el
  gatillo (si no, el web loop non-streaming disparaba un request extra).
- **Ramas de log**: `nudge_retry` (el retry trae tool_calls → se emiten como
  function_call), `nudge_confirm` ("ok" → cierre real con el texto original),
  `nudge_noop` (otro texto → se descarta). `intent` con `isFutureIntentNarration`
  queda solo como telemetría (ya NO gatilla).
- **Coste**: +1 request por respuesta final legítima con tools del usuario y sin
  haber ejecutado tools. El "ok" nunca aparece como texto visible para el usuario.
