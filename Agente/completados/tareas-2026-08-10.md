## 10826-1 — Fix "falso complete" en el bridge de Codex Desktop

**Qué se hizo** (plan: `Agente/planes/completados/plan-anti-falso-complete-2026-08-10.md`):

El bridge ahora ataca el patrón en que el modelo (DeepSeek V4 Flash vía Codex Desktop)
narra una intención ("voy a...", "lo reintento") en texto, no invoca ninguna tool y
Codex cierra el turno con `task_complete` automático → el usuario "ve que se detuvo o
continúa" sin poder distinguirlo. Mitigación en 3 capas:

- **Capa A (preventiva)**: si hay tools y una conversación real, se inyecta
  `EXECUTION_DIRECTIVE` (system) al final: "si anuncias una acción, ejecútala antes de
  finalizar". No muta el system de Codex.
- **Capa B (nudge)**: si la respuesta final es narrativa de intención futura
  (`isFutureIntentNarration`, regex) y no hubo tool_calls, se hace UN retry acotado
  (`NUDGE_RETRIES=1`, timeout `NUDGE_TIMEOUT_MS`) con `NUDGE_DIRECTIVE`
  ("Continúa: ejecuta ahora la acción que anunciaste"). Si el retry trae tool_calls,
  se emiten como function_call normales (con reasoning asociado); si no, se descarta.
- **Capa C (telemetría)**: logs `nudge_retry` (routedVia/textLen/toolNames),
  `nudge_noop` y `nudge_error` para medir frecuencia real.
