## Alcance y aislamiento

- `freellmapi` no fue reseteado, podado, renombrado ni repuntado.
- GloryAPI se derivó desde un commit sanitizado mediante `git archive` y overlay allowlisted.
- El nuevo checkout tiene Git independiente, rama local `gloryapi`, `HEAD` propio `b6db7a8` y no tiene remoto.
- No se copiaron `.env`, SQLite/WAL/SHM, `node_modules`, builds, logs, PID, junctions ni utilidades sensibles.
- GloryAPI usa loopback y defaults separados: API `127.0.0.1:3101`, bridge `127.0.0.1:4100` y SQLite `server/data/gloryapi.db`.
- El estado del legado sigue siendo ajeno a este workspace; sus modificaciones preexistentes no se atribuyen a esta tarea.

## Escaneo histórico, bootstrap y política del legado

- El historial candidato de `freellmapi` se revisó sin imprimir valores: **518 commits y 4.018 blobs**.
- El overlay actual se revisó con patrones de claves privadas, prefijos de proveedores, claves cloud,
  access keys y bearer literals. Las coincidencias quedaron limitadas a fixtures sintéticos de tests;
  no hubo coincidencias en producción ni en la documentación canónica.
- Los artefactos sensibles y utilidades temporales ya identificados permanecen fuera del overlay según
  `overlay-manifest-2026-08-10.tsv`; por esa razón el historial completo no se considera publicable.
- La decisión reproducible es mantener el árbol sanitizado derivado por `git archive` + overlay allowlisted,
  con Git independiente. El guard confirmó `.git-common-dir` dentro de GloryAPI, ausencia de alternates,
  `.git` no simbólico y ausencia de remotos.
- Política de cambios de `freellmapi`: no se modifica durante esta migración. Una corrección operativa
  futura deberá registrar path, motivo, evidencia, pruebas, impacto y decisión de portabilidad; se prohíben
  el desarrollo paralelo silencioso y la sincronización bidireccional automática.

  detrás de `NODE_ENV`; el default de tests conserva el camino histórico para que las pruebas de migraciones sigan
